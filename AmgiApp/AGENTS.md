# AmgiApp

The Xcode project, generated by xcodegen from `project.yml` and not tracked —
run `xcodegen generate` after cloning and after any `project.yml` change. The
`.pbxproj` is output, never input.

## Targets

- **AmgiApp** (iOS) — links `RootFeature` and `IntentsFeature`, the WidgetKit
  SDK, and the embedded `AmgiWidget`. `Sources/AmgiAppApp.swift` is 13 lines:
  `@main`, an `init` calling `AmgiRoot.bootstrap()`, a `body` returning
  `RootView()`. `Sources/Intents/AmgiShortcuts.swift` is the only other root
  file.
- **AmgiWidget** — links `WidgetFeature` alone. Keep its deps narrow: it reads
  the app group and has no business reaching the engine.
- **AmgiWatchApp** — links `WatchFeature` plus the full engine, because
  `@main WatchApp.swift` bootstraps the collection itself.

`Sources/Watch` and `Sources/Widgets` sit in `AmgiApp.sources.excludes`, so the
iOS target proper is those two root files.

## Rules

- **No per-file `path:` entries under `Sources/`.** Cross-target file sharing
  goes through an SPM product — `ReviewCore` exists because `project.yml` used
  to cherry-pick three files into the watch target by path, compiling them twice
  as two distinct types.
- **`AppShortcutsProvider` belongs to the app target.** Built from
  `IntentsFeature`, the intents extract fine (the merged `Metadata.appintents`
  names all three) but `autoShortcuts` comes out empty, so the Siri and
  Spotlight phrases never reach the app. Verified both ways; keep
  `AmgiShortcuts.swift` here.
- **A `@Dependency` property on an `AppIntent` does not work** — see
  `SyncIntentRunner` for the shape that does.
- **`LM_SKIP_METADATA_EXTRACTION` stays off.** Setting it stops Xcode scheduling
  `ExtractAppIntentsMetadata` at all, so the app ships no `Metadata.appintents`
  and nothing in `IntentsFeature` reaches Shortcuts. The price of leaving it off
  is a launch-time "Failed to instantiate type …" line for the widget intent the
  app does not link.
- **AppIntents metadata does extract from a SwiftPM target** — the built
  `AmgiWidget.appex` carries a complete `extract.actionsdata`.

## Xcode writes to the generated project

With the project open, Xcode writes `DEVELOPMENT_TEAM`, `CODE_SIGN_STYLE` and
scheme-version bumps into `project.pbxproj` and `AmgiApp.xcscheme`. The project
is gitignored, so this costs nothing as long as `project.yml` stays the place
you edit — re-run `xcodegen generate` to get back to a known state.
